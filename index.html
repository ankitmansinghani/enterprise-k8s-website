What's covered in a K8s Cluster Audit

Every audit walks through these six domains. Click any to see the checks.

1Security & RBAC
  • RBAC least privilege review across all ServiceAccounts and ClusterRoles
  • Pod Security Standards (baseline / restricted) enforcement
  • Network Policies — default-deny posture and namespace isolation
  • Secrets encryption at rest (etcd encryption providers)
  • Service Account token expiry and projected token usage
2Networking
  • CNI configuration review (Cilium, Calico, Flannel) and MTU tuning
  • DNS performance — CoreDNS sizing, cache hit ratio, NodeLocal DNS
  • Ingress TLS termination, certificate rotation, and SNI handling
  • Service mesh readiness (Istio / Linkerd) and sidecar resource impact
  • Network Policy coverage across workloads and east-west traffic paths
3Resources
  • Resource requests and limits set on every pod — no noisy neighbors
  • LimitRange and ResourceQuota policies per namespace
  • Horizontal Pod Autoscaler configuration and metric source validation
  • Node capacity planning and bin-packing efficiency review
4Reliability
  • PodDisruptionBudgets for all critical workloads
  • Multi-replica deployments with proper anti-affinity spread
  • Liveness, readiness, and startup probes correctly configured
  • Node affinity and taint/toleration strategy for hardware isolation
5Observability
  • Prometheus and metrics-server deployment, scrape config, retention
  • Log aggregation pipeline (Loki, Fluent Bit, ELK) and PII handling
  • Alerting rules — SLO-driven, deduplicated, and routed correctly
  • Distributed tracing (Tempo, Jaeger) coverage on critical paths
6Lifecycle
  • Upgrade path assessment — control plane and node version skew
  • Deprecated API usage scan and migration plan
  • Image tag policies — no :latest, signed images, vulnerability scanning
  • CI/CD integration — GitOps workflow, drift detection, rollback safety
